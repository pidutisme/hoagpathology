# HOAG Pathology V4 – Fix Notes

## Issues found

### 1. Visitor controls outside `#moduleYearGrid`
The Visitor restriction selector was heavily scoped to `#moduleYearGrid`. The Inventory write forms (`inventoryMovementForm` and `inventoryAdminItemForm`) are rendered outside that container, so some disabled controls were not being marked with the Visitor disabled class. Their native/default cursor could therefore remain visible.

### 2. Inventory custom write control
The Inventory item custom trigger (`#inventoryItemTrigger`) was not included in the Visitor lock list. It is now explicitly disabled for VISITOR users.

### 3. Visitor keyboard guard typo
The keydown guard used `if (!isVisitorRole_)` instead of calling `isVisitorRole_()`. This has been corrected.

### 4. Session identity race
The startup `/api/login-state` request can run at the same time as a manual login or logout. A late response from an older authentication check could theoretically apply an older identity after a newer login had already completed. This is the likely cause of the brief wrong-user / wrong-role behaviour previously observed during refresh/login transitions.

V4 now uses a monotonic authentication generation counter. Every login/logout invalidates older asynchronous auth checks. Startup and periodic session verification responses are ignored when they belong to an older generation.

### 5. Service Worker cache version
The Service Worker cache name was bumped from `v6` to `v7` so the patched JavaScript/CSS is not unnecessarily held behind the previous static-asset cache.

## Important note about automatic login
V4 intentionally restores a valid HttpOnly session cookie on refresh/startup. The login cookie currently has a 6-hour lifetime. Therefore, opening the application while a valid session still exists can automatically sign the previous authenticated account back in.

That behaviour is separate from the identity-race bug. If the desired policy is instead **"closing the application/browser must always require a new login"**, the session policy should be changed separately rather than weakening the current server-side session validation.

## V4 FIXED – Additional Corrections (2026-10-31)

### 1. Visitor cursor and fill-control coverage
- Visitor write-control detection is no longer limited to `#moduleYearGrid`.
- Inventory forms and controls outside the year-grid container are now covered.
- Inventory Stock In/Stock Out, Inventory Control, item selector trigger, save/clear controls and dynamically generated inventory controls are disabled for VISITOR.
- Disabled controls and their child SVG/icon elements use `cursor: not-allowed`.
- Visitor keyboard/click guards continue to block mutation controls.

### 2. Year-card sizing
- Annual/module year cards were reduced to a compact 96px footprint.
- Final CSS overrides prevent legacy responsive rules from stretching year cards.
- Asset query version was bumped to `visitor-v5` so browsers fetch the updated CSS.

### 3. Session lifecycle policy
The authentication lifecycle now follows this exact policy:

`OPEN URL / APP -> LOGIN -> ENTER WEBSITE -> REFRESH = STAY LOGGED IN -> CLOSE TAB / APP = LOG OUT`

Implementation:
- A tab-scoped authentication marker is stored only in `sessionStorage`.
- A brand-new page/tab/app instance never restores an existing HttpOnly cookie automatically; the login screen is shown.
- A normal refresh retains the tab marker and performs authoritative `/api/login-state` verification before restoring the current user and role.
- `pagehide`/`beforeunload` sends a keepalive POST to `/api/logout` when the tab/app is closed or navigated away from, while reloads are excluded.
- Electron desktop close has a main-process logout fallback that reads the current session cookie and calls `/api/logout` before destroying the window.
- Manual logout clears the tab marker as well.

- `node scripts/build.mjs`: PASS – 60 files checked.
